# HyperPulse v0.7 서비스 개선 계획 — 2026-11-14

상태: 계획 수립. 아래 구현 체크박스는 검증이 끝난 뒤에만 완료 처리한다.
이 문서는 v0.7의 실행 백로그다. [제품 백로그](PRODUCT_BACKLOG.md)는 전체 기능,
[런칭 플랜](LAUNCH_PLAN.md)은 배포 및 공개 승인 기준을 관리한다.
v0.7은 제품 범위이며 이 문서만으로 실제 출시나 API 버전 변경을 의미하지 않는다.

## 제품 목표와 출시 메시지

대상은 Hyperliquid에서 자주 거래하지만 여러 화면을 상시 감시하기 어려운 트레이더다.
**웹에서 장을 읽고 → Telegram에서 의미 있는 변화를 받고 → 웹에서 근거와 결과를 확인한다.**
핵심 약속: “Hyperliquid에서 달라진 포지션을 빠르게 파악하고, 중요한 고래 움직임은
Telegram에서 확인하세요. 확인된 체결은 근거까지 볼 수 있습니다.”

| 참고 서비스 | 가져올 제품 패턴 | 가져오지 않을 것 |
|---|---|---|
| [Binance AI / AI Pro](https://www.binance.com/en/square/post/377233031745733) | 요약 → 이상 변화 → 근거·검토로 이어지는 동선 | 자유형 챗, 자동 주문, 계정 전체 개인화 |
| [Hyperliquid Portfolio](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/portfolio-graphs) · [HyperTracker](https://docs.coinmarketman.com/hypertracker-dashboard) | 포지션과 성과를 구분하고 집계에서 지갑으로 내려가는 구조 | 내 계정 대시보드 복제, 전체 지갑 인덱싱 |
| [Nansen Smart Alerts](https://release.nansen.ai/changelog/smart-alerts-on-hyperliquid) · [Hyperdash](https://hyperdash.com/learn/how-to-read-a-liquidation-heatmap) · [CoinGlass](https://www.coinglass.com/hyperliquid) | 놓치면 아쉬운 사건을 짧게 전하고 필요할 때 상세 확인 | 최고 속도·시장 전체 커버리지 주장, 대형 히트맵 복제 |

기능 수가 아니라 **세션 재방문, 알림 구독 이유, 결과 확인**을 검증한다.
비교는 각 서비스의 공개 설명 기준이며 수익성이나 사용자 유지 효과를 입증한 것은 아니다.

## 단계 1 — 세션 시작 브리프 (P0)

사용자 질문: “지난 브리프 이후 뭐가 달라졌고, 지금 뭘 확인해야 하지?”
기존 Market Brief·Home 티저·세션 발송을 확장한다. 실시간 웹 Brief와 발행된
세션 Brief를 구분하고, 새 외부 수집이나 추가 LLM 호출 없이 먼저 규칙으로 계산한다.

- [ ] **V07-01 세션 스냅샷 계약:** 기존 판단 근거 저장을 재사용할 수 있는지 확인하고,
  세션 ID·발행/관측 시각·시장 범위·가격·funding·고래 포지션 표본·근거 ID를 고정한다.
  직전 **발행된 시장 전체 세션**을 비교 기준으로 삼고 재시작 후에도 유지한다.
  같은 세션 재시도는 같은 스냅샷을 참조한다. 필요 시 추가 스키마를 별도 검증한다.
- [ ] **V07-02 변화 선택 규칙:** 같은 자산·단위·비교 가능한 표본만 비교한다.
  Top3 구성/표본 변경, 오래된 입력, 기준 데이터 없음은 구분하고 비교를 강제하지 않는다.
  발행 전 기준·동률 순서를 테스트로 고정해 가장 중요한 변화 1~2개만 선택한다.
- [ ] **V07-03 Home·Insights 표시:** 변화 → 해석 → 재확인 조건 순서로 표시한다.
  변동 미미와 데이터 부족을 다르게 표시한다. 현재 스냅샷과 과거 근거를 섞지 않는다.
  모바일에서 표를 열지 않고 핵심을 읽고 근거로 이동할 수 있어야 한다.
- [ ] **V07-04 세션 Telegram 연결:** 웹과 같은 발행 스냅샷으로 핵심 변화 한 줄과
  상세 링크를 보낸다. Asia 09:00 KST / US 09:00 ET, 90분 창, 슬롯당 1회 유지.

**핵심 테스트:** 첫 세션, 무변화, 자산/표본 변경, stale, 재시작 후 동일 세션,
US DST 및 발송 중복, 390px Home → Insights → 근거. 발송은 대역으로 검증한다.

## 단계 2 — 검증 가능한 고래 변동 알림 (P0)

사용자 질문: “이 고래가 뭘 했고, 이 알림이 왜 지금 왔지?”
기존 Whale Move를 개선한다. 초기에는 단일 채널과 현재 발송 상한을 유지한다.

- [ ] **V07-05 트리거 이유 표준화:** 진입·증액·축소·종료·방향 전환을 구분하고,
  어떤 변화가 어떤 발송 조건을 충족했는지 한 줄로 표기한다.
  포지션 증액과 가격에 따른 평가액 변동이 혼동되지 않는지 확인한다.
- [ ] **V07-06 체결·포지션 표시 검증:** 이번 거래 금액·검증 체결가 범위와
  변화 후 총 포지션·평균 진입가를 분리한다. 미검증은 스냅샷 변화로 명시하고
  최신 체결가나 tx 링크를 추정하지 않는다. Telegram·웹 이력의 의미를 맞춘다.
- [ ] **V07-07 근거 열람과 운영 검수:** 정상 Beta 사용자가 Telegram에서 해당
  판단 근거를 열 수 있게 한다. 기존 별도 evidence 쿠키와 초대 로그인 간 연결은
  접근 정책을 검토하고, 비밀값을 URL에 넣거나 백엔드 보호를 약화시키지 않는다.
  표본 검수에는 원천/발송 시각, 중복, 링크 정합성, 실패 원인을 남긴다.

**핵심 테스트:** 증액·축소·종료·전환, 동일 금액의 서로 다른 이벤트, 동일 이벤트
재시도, 지연·미검증 체결, explorer 링크, 초대/비인가 근거 조회. fills 조회는
기존 이벤트 한정 예산을 유지한다. LIQ WATCH/DANGER는 실제 liquidationPx만 쓰며,
검증되지 않은 청산 이벤트를 시장 전체 데이터로 표시하지 않는다.

## 단계 3 — 시그널 성적표 (P1)

사용자 질문: “어제 본 시그널이 실제로 어떻게 됐지?” 기존 rules_v1 15m Pulse가
출발점이다. 단계 1부터 기존 기록의 누락 여부를 점검하되, 평가 계약 고정 전에는
공개 집계에 포함하지 않는다. 초기에는 다른 종류의 알림이나 1시간 평가를 섞지 않는다.

- [ ] **V07-08 평가 계약 고정:** 발행 시각·기준 mark·방향/Wait·엔진 버전·근거 ID,
  15분 목표 시각·허용 관측 오차·결과 mark·실제 관측 시각을 정의한다.
  기존 Pulse 저장/해결 로직과 대조하고 누락·지연 데이터와 과거 불완전 기록을
  사후 보정해 성공으로 집계하지 않는다. 평가 계약이 바뀌면 버전을 분리한다.
- [ ] **V07-09 조회 API·웹 성적표:** 기간과 자산별로 맞음·빗나감·Wait·평가 대기·
  관측 불가를 모두 제공한다. 발행 당시 판단·근거와 결과를 연결한다. 방향 적중률을
  노출할 경우 분모(평가 가능한 방향 신호)와 제외 건수, 기간, 표본 크기를 함께 표시한다.
- [ ] **V07-10 공개 검수:** 고정 표본을 원천과 대조하고 손실 구간·누락이 숨겨지지
  않는지 확인한다. 가격 방향 결과는 수익률이 아니며 체결·비용을 반영하지 않는다.
  1시간 평가는 별도 범위다. $1,000 Paper Portfolio는 기존 30일·100개 완료 거래
  및 데이터·비용 검증 기준을 그대로 유지하며 성적표로 대체하거나 앞당기지 않는다.

**핵심 테스트:** 맞음/빗나감/Wait, 목표 시각 전후·허용 범위 밖의 mark,
누락·재시도·중복 해결, 버전별 분모, 저장된 근거 불변성, 전체 결과 조회.

## 단계 4 — Closed Beta 검증과 출시 판정 (P0 게이트)

- [ ] **V07-11 행동 측정:** 브리프 열람자 중 다음 세션 재방문, Telegram에서
  알림→근거 링크 유입, 성적표 재열람을 본다. 가능한 관측 범위와 분모를 기록한다.
  Telegram의 개인별 읽음·뮤트 여부를 안다고 가정하지 않고 채널 집계와 인터뷰를 사용한다.
- [ ] **V07-12 실제 배포 검증:** Vercel Preview + 별도 HTTPS API에서 초대·권한,
  390px Home/Insights/Alerts, 신선도/누락, deep link, 재시작·중복 발송을 확인한다.
  운영 Telegram 발송과 공개 전환은 별도 승인으로 진행한다.
- [ ] **V07-13 메시지 검증:** Home CTA는 최신 브리프, 상세 CTA는 Telegram 가입·
  근거·결과 확인에 집중한다. 소규모 Beta에서 ‘무엇이 달라졌는가’, ‘왜 이 알림이
  왔는가’, ‘결과가 무엇인가’를 사용자 스스로 설명할 수 있는지 확인한다.

구현 순서는 **1 → 2 → 3 → 4**. 데이터 계약과 사용자 표시를 티켓별로 검증한 뒤
커밋하고, 단계별 통과 결과와 잔여 항목을 이 문서에 남긴다. v0.7 단계 1·2 개선과
기존 배포 준비는 병행할 수 있으나, 검증되지 않은 기능을 완료로 표시하지 않는다.
성적표 표본 부족만으로 제한 Beta를 연기할 필요는 없지만 성과 홍보는 보류한다.
초대 접근, 운영 DB 복구·롤백, 검증된 청산 소스 등 [런칭 게이트](LAUNCH_PLAN.md)는
그대로 유지한다. 당장 유료화, 개인별 Telegram 라우팅, 실제 주문, 전수 추적은 제외한다.
